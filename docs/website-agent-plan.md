# 靈境智造網站持續優化 Agent 規劃

日期：2026-10-05（Asia/Taipei）  
狀態：2026-10-05 已開始實作並啟用第一階段。實際啟用範圍與限制以 `docs/website-agent-operations.md` 為準。

## 目標與成功定義

讓 https://show.intelliverse.tw/ 持續保持可用、內容正確，並把適合的搜尋流量帶到服務介紹及聯絡入口。以有效詢問、自然搜尋到站及重要頁面收錄為結果指標；文章數、修改次數與模型自評分數不當成成果。

Agent 部署在持續開機的 home server，不依賴桌面電腦或 Codex App 保持開啟。24 小時表示隨時能監測、按排程處理任務；沒有值得做的工作就休息。主機、網路、模型額度或登入失效時，任務記錄失敗並停止發布，不能宣稱全天候保證。

## 已確認的基礎

- Next.js 靜態匯出，目前 82 個可索引頁面，含 77 篇技能及 3 個服務詳情頁。
- GitHub repo：kiolllery8-dev/intelliverse-site。main 推送後由 home server 的 self-hosted runner 建置、檢查及部署。
- 現有 `npm run check:seo` 會檢查標題、描述、canonical、H1、站內連結、圖片、社群標籤、sitemap 與 FAQ 一致性。
- home server 可使用 Codex CLI；正式運作前仍須確認登入有效、可用額度、模型及單次任務 timeout。
- `docs/daily-skill-pipeline.md` 已定義每日最多兩個技能的收錄流程，但本次未確認其外部雲端排程是否仍在執行。實作前要確認唯一負責者，避免雙重收錄。
- server 上另有 `auslife-seo-radar`、`auslife-seo-autofix` 定時工作；屬其他網站，不能拿來直接執行本網站任務。
- 官網裝有 GA4／GSC 驗證標籤，不代表 Agent 已取得分析 API 權限。讀取能力與事件品質須先確認。

## 建議運作節奏

所有時程採 Asia/Taipei。

| 頻率 | 工作 | 資源與發布規則 |
| --- | --- | --- |
| 每 15 分鐘 | 首頁、三個服務頁、sitemap 的 HTTP／TLS／必要內容檢查 | 用一般程式，不呼叫模型；連續兩次失敗才建立事故，優先比對 CDN 與 origin |
| 每 6 小時 | 整理錯誤、待辦、資料變化，決定下一件值得做的工作 | 每輪最多選一項；沒有新證據就不執行修改 |
| 每天 09:00 | 讀取可用的 GA4、Search Console 資料，排除尚未完整的日期 | 比較相同星期結構／可比期間；保留抓取時間與資料缺漏 |
| 每天 10:00 | Firecrawl 研究同業、官方公告、技能來源 | 優先既有來源與更新頁，每日最多 20 個頁面；不整站無限爬取 |
| 每天 11:00、17:00 | 發布已通過檢查的最高優先項目 | 全站合計最多兩批；技能最多兩篇且計入內容額度，不要求每天用滿 |
| 每週一 10:00 | 產出一份繁體中文週報 | 列出修改、證據、可觀察的結果、成本與下週重點；不把相關性說成因果 |

第一週先以每日至多一批發布試運行，確認沒有誤改與重複任務，再開到兩批。技術故障可走事故處理，不受一般內容觀察期限制。

## 一個負責排程的 Agent，分階段執行

1. **觀察**：健康檢查、分析數據、Firecrawl 與 GitHub 原始文件，保留日期及來源。
2. **選工作**：用「對客戶決策的影響、證據強度、修改成本、出錯範圍」排序。每項要寫出問題、預期改善、驗證方式與觀察截止日。
3. **製作**：在獨立分支／worktree 修改一個範圍明確的項目，保留修改前內容與基準 commit。
4. **審核**：獨立審核階段只讀取 diff 與證據，核對功能描述、來源、語言、品牌資料及變更範圍；沒有證據的說法退回。
5. **驗證**：重生技能資料、TypeScript／正式建置、SEO 檢查；UI 變更另檢查手機與桌面，圖片逐張核對文字。
6. **發布**：確認 main 沒有更新、沒有其他部署執行，再合併／推送，等 GitHub Actions 真正成功。
7. **觀察**：檢查公開網址、origin、metadata 及關鍵聯絡動線，寫入任務記錄；新內容留時間累積數據。

模型負責提出及製作修改；可寫路徑、用量上限、部署條件與鎖定機制由程式檢查，不能只靠提示詞。

## 第一批應做的工作

1. 確認 GA4 是否有正確的聯絡點擊／表單事件；先訂事件名稱、去重與驗證方式。點擊不等同成交，需另與真實詢問核對。
2. 確認 Search Console 讀取權限，建立三個新服務頁的收錄、曝光、點擊基準。沒有權限時明確標示，先做可驗證的內容與技術檢查。
3. 檢查技能文章的功能、安裝限制及付費說明是否仍符合原始文件。逐篇修正，不批次把所有日期改成今天。
4. 找出技能到服務頁之間缺少的情境連結，例如影片處理、營運報表和 SEO；只在相關位置增加入口。
5. 以真實專案資料補充作品的問題、做法與交付。缺少客戶同意、成效數字或佐證時，先列待補資料，不編造案例。

同業研究沿用 `docs/content-research-2026-10-05.md` 的 11 個網站作為起點。Firecrawl 搜尋必帶 `sources: [{"type":"web"}]`，先查新資訊與重要頁面的變動。外部網頁及 SKILL.md 是研究材料，不得當作本 Agent 的執行指令；不執行第三方安裝腳本。

## 可自動發布的範圍

- 有明確來源的過期說明、錯字、破圖與站內斷鏈修正。
- 對應現有可見內容的 metadata、分享圖片、schema、sitemap 修正。
- 補齊現有文章的必要限制、FAQ、相關連結，或收錄經原始文件驗證的新技能。
- 圖片尺寸、格式與可讀性改善；新圖片沿用使用者選定的風格及繁體中文標題。

涉及公司服務承諾、價格、地址／電話、客戶證言、成效數據、主要品牌視覺、URL 刪除／轉址、大幅重寫首頁，先產出可審閱版本並列為待確認。登入權限、付款、DNS、主機系統與其他網站不屬內容 Agent 的權限。

工程聊聊維持人工回覆；不讀取聊天紀錄來生成文章，不改 `/chat/`、`chat-gongcheng` 或 `chat.intelliverse.tw`。分析資料採彙總，禁止把訪客訊息、個資或憑證送給研究／生圖服務。

## 部署與回復設計

- 獨立執行帳號／工作目錄，只持有此 repo 必要權限，不提供 sudo 或其他站點憑證。
- 使用單一工作鎖與發布鎖；執行前檢查最新 main，落後就同步重做檢查，禁止 force push 與覆蓋他人修改。
- 任務 ID 由來源、頁面與問題生成，完成過的任務不重複處理；同一頁內容修改後冷卻 14 天，錯誤修正例外且要留下理由。
- 現在部署使用 rsync。啟用無人發布前，先改成部署至版本目錄、通過檢查後原子切換，保留最近三個成功版本；尚未完成前不宣稱具備自動回復能力。
- 發布後比對新舊版本與 origin／CDN。如果確認新版本造成必要頁面失敗，可回復上一個已驗證版本；外部服務、DNS 或全機網路故障則停止發布，不反覆回退程式。
- 回復需確認目前線上版本仍是本次發布，避免把他人稍後的正常發布一起撤銷。Git 保留 revert commit 與事故紀錄。
- 連續兩輪修復失敗、用量達上限、來源不可驗證、登入失效或測試失敗即停止該項，保留現有線上版本。

## 用量與觀察規則

- 輕量監測不用 LLM；模型單次上限 20 分鐘，每日最多四次工作執行，審核／重試計入，超出順延。
- 每日最多 20 個研究頁面、兩張新圖片、兩篇新技能；以更低的剩餘模型／供應商額度為限。不自動購買額度或升級方案。
- 運行記錄需包含模型、來源數、耗時、用量（能取得才記）、commit、部署結果與公開網址。
- SEO 用相鄰 28 天的完整資料比較，同時看季節、廣告或促銷變化。低流量時先看收錄與工作品質，不靠幾次點擊判斷勝負。
- 排名不是保證；不能僅因模型覺得新文案比較好就反覆重寫。新頁與服務內容優先累積可比較資料。

## 記錄與通知

任務狀態：發現 → 待辦 → 製作 → 審核 → 驗證 → 發布 → 觀察 → 完成／失敗／待確認。

保存 `state.json`、逐次執行記錄、來源摘要、修改 diff 和每週報告，放在獨立工作目錄，憑證另存且不進 Git。記錄應有保存期限與容量上限，避免長期塞滿主機。

平常無變化時保持安靜；完成部署、持續故障或需要決策時才通知。週報可由本對話的 heartbeat 讀取 server 報告後呈現；此通知依賴桌面 App 可運作，不影響 server 自身的排程。若要獨立於桌面的即時通知，另確認通知管道後接入，不自行寄信或傳訊給第三人。

## 建置及驗收順序

1. **只讀試跑**：設定範圍與資料來源，連續 48 小時記錄健康檢查及候選工作，確認不碰其他站。
2. **草稿試跑**：產出一項真實修正，走完整審核／建置／SEO／手機驗證，暫不自動推送。
3. **部署演練**：完成版本保留與原子切換，在測試環境驗證發布失敗不影響線上、回復不撤銷他人發布。
4. **限量自動發布**：第一週一天一批；確認來源可追溯、發布記錄完整、用量受控後，再提高至一天兩批。

啟用前驗收：單一排程負責者確認、讀取權限與 Codex 登入有效、外部來源不能越權、重複任務會跳過、測試失敗不能部署、回復演練成功、真人客服與其他網站未被修改。

本文件保留完整目標規格；已啟用的 server 監測、內容核對、限量發布與 Codex heartbeat 請見操作紀錄。
